1. Business Use Case — Why Agentic AI?
1.1 The Company

Prodapt is a mid-size telecom provider offering mobile voice, 4G LTE, and 5G data
    services across the United States. It serves consumer, business, and enterprise customers. Like every telecom
    operator, Prodapt receives thousands of inquiries daily about network problems, billing disputes, roaming,
    device upgrades, and service-level agreements (SLAs).
  

    Today, these inquiries are handled by separate teams using separate tools. Your capstone project automates
    this fragmented workflow using a multi-agent AI Operations Center.
  
1.2 Who Uses the System?

Customer Support Agent (primary user)
    Front-line staff who receive customer calls and chats. They need fast, accurate answers and often must
    coordinate between policy documents, network data, and billing systems — usually while the customer waits on hold.
  

Network Operations (NOC) staff
    Engineers who monitor tower status, diagnose connectivity issues, and manage open incidents. Their expertise
    is technical; customer-facing explanations require a different tone.
  

Billing Resolution team
    Specialists who investigate duplicate charges, apply credits, and follow dispute policy. Actions must comply
    with credit limits and leave an audit trail in the billing database.
  

End customer (indirect beneficiary)
    Subscribers who expect one answer — not three transfers — when they ask: "My 5G keeps dropping and I was
    charged twice — am I owed a credit?"

1.3 The Existing Problem (As-Is — Manual Operations)

    Before automation, a single customer inquiry can touch four disconnected systems and
    three different teams. There is no intelligent routing — humans decide where to look.
  


Today's pain points

Fragmented knowledge — Policies live in PDF/TXT documents; outage and tower data live in SQL databases; live diagnostics sit in NOC dashboards; billing data sits in a separate CRM/billing system.
Slow resolution — An agent puts the customer on hold, searches policy folders, emails NOC, waits for a billing supervisor, then manually drafts a reply. Average handle time: 15–25 minutes for complex cases.
Inconsistent answers — Two agents may interpret the roaming policy or SLA credit rules differently because answers are not grounded in the same source documents.
Wrong-team routing — Billing agents cannot diagnose tower issues; NOC engineers should not apply credits. Customers get transferred multiple times.
Multi-domain questions fail — Questions like "We had a 6-hour Midwest outage — am I eligible for SLA credit?" require both operational data and policy interpretation. No single tool handles both.
High training cost — New hires need weeks to learn which system to use for which question type.
No audit trail — It is hard to prove which data sources and policies were consulted when a credit was applied or a diagnosis was given.



What the business needs

One entry point where staff (or customers) ask a question in plain English
Automatic routing to the right specialist — policy, analytics, network, or billing
Answers grounded in actual policy documents and live database records
Actionable outcomes — diagnostics run, credits applied — with data persisted in SQL
Professional, consistent customer-ready responses every time
Visibility into which agents ran and what they found (execution trace)
Ability to scale specialist services independently (network vs billing microservices)

    customer-ready response.

5. Database Design & Usage Rules

No in-memory dictionaries

      Do not store tower status, billing accounts, charges, or incidents in Python dictionaries,
      lists, or global variables. Every ADK tool must query or update SQLite. This mirrors real
      production systems where agents interact with persistent data stores.
    

5.1 Tables Provided in 01_schema.sql

TableUsed ByPurpose

network_towersLlamaIndex SQL, Network Diagnostics ADKTower inventory: region, city, technology, status
network_outagesLlamaIndex SQLHistorical outage records with severity and root cause
tower_performanceLlamaIndex SQL, Network Diagnostics ADKLatency, packet loss, throughput, signal strength
open_incidentsNetwork Diagnostics ADKActive NOC incidents linked to towers
customer_subscriptionsLlamaIndex SQLPlan names, fees, account types by region
billing_accountsBilling Resolution ADKCurrent balance per customer

billing_creditsBilling Resolution ADKApplied or pending credits (insert on credit approval)
billing_disputesBilling Resolution ADKOpen and resolved dispute records


5.2 How Each Component Uses the Database

ComponentDatabase Interaction


LlamaIndex Semantic SQL
Connect via SQLDatabase wrapper. ObjectIndex selects relevant tables; query engine generates and runs SQL. Read-only for analytics scenarios.


Network Diagnostics ADK tools

check_tower_status — JOIN network_towers with the latest tower_performance row (maximum recorded_at for that tower, not an average of the week) and open_incidents.
run_connectivity_diagnostics — Read tower status and performance; return recommendations based on SQL results.
get_regional_network_summary — Aggregate tower counts and statuses by region from SQL.
        


Billing Resolution ADK tools

lookup_billing_account — SELECT from billing_accounts and the customer's charges. current_balance matches invoice_status = 'OPEN'. Rows with invoice_status = 'PAID' are prior months and are not added into the balance again.
check_duplicate_charges — same customer, same description, and same billing period, or is_duplicate_flag = 1. The same plan name in an earlier month is not a duplicate. Skip a charge that already has an APPLIED credit.
apply_billing_credit — INSERT into billing_credits. If the amount is 50.00 USD or less, status is APPLIED and current_balance is reduced. If the amount is over 50.00 USD, status is PENDING_APPROVAL and current_balance is left unchanged.

6. Detailed Build Instructions (No Code — Design Only)
6.1 LlamaIndex Document RAG (document_rag.py)

Configure a local embedding model (HuggingFace all-MiniLM-L6-v2 is recommended from your lab).
Load all TXT files from data/documents/ using SimpleDirectoryReader.
Build a VectorStoreIndex and persist embeddings to data/vector_index/ so rebuilds are not required every run.
Expose a single function that accepts a natural language question and returns a string answer.
Use as_query_engine — not LlamaIndex agents, workflows, or ReAct patterns.

6.2 LlamaIndex Semantic SQL (sql_semantic_search.py)

Connect to data/telecom_ops.db using the LlamaIndex SQLDatabase wrapper.
Create SQLTableNodeMapping for all tables in the schema.
Define SQLTableSchema objects with context strings for semantic table selection.
Build ObjectIndex over table schemas using VectorStoreIndex.
Create SQLTableRetrieverQueryEngine with similarity_top_k of 1 or 2.
Expose a single function that accepts a question and returns the synthesized answer.

6.3 Network Diagnostics ADK Service (port 8001)

Create a Google ADK Agent with a clear instruction describing NOC diagnostics responsibilities.
Implement three async tools — each tool opens a SQLite connection and runs SQL:
      
check_tower_status(tower_id) — returns status, technology, signal metrics, any open incident
run_connectivity_diagnostics(tower_id, symptom) — reads tower data from SQL, returns recommendations
get_regional_network_summary(region) — aggregates tower health for a region from SQL


Wrap the agent with to_a2a and run with uvicorn on port 8001.
Verify the agent card is published at localhost:8001/.well-known/agent-card.json

6.4 Billing Resolution ADK Service (port 8002)

Create a Google ADK Agent for billing dispute resolution.
Implement three async tools — all SQL-backed:
      
lookup_billing_account(customer_id) — balance and recent charges from SQL
check_duplicate_charges(customer_id) — find flagged duplicates in billing_charges
apply_billing_credit(customer_id, amount, reason) — INSERT credit row, UPDATE account balance; use PENDING_APPROVAL in SQL when amount exceeds policy auto-approval limit ($50 per billing_disputes_policy.txt)


Expose via to_a2a on port 8002.

6.5 LangGraph Remote ADK Client (adk_remote_client.py)

Create RemoteA2aAgent instances pointing to each agent card URL.
Wrap each remote agent in a lightweight proxy ADK Agent with the remote as sub_agent.
Use ADK Runner.run_async to send messages and collect final responses.
Expose synchronous wrapper functions for use inside LangGraph nodes (Network Diagnostics and Billing Resolution).
Handle service-unavailable errors gracefully with a clear message if ports 8001/8002 are not running.

6.6 CrewAI Customer Communications (crew_nodes.py)

Create a two-agent sequential crew:
      
Communications Specialist — drafts response using original query + accumulated agent_context from prior workers
Quality Reviewer — reviews for accuracy, tone, and policy compliance; outputs final text only


Use Process.sequential. Reviewer task depends on drafter task output.
Expose one function: accepts user query and context string, returns final customer-ready response.

How to read the seed

network_towers has 10 rows. Each tower has several tower_performance samples. Diagnostics and packet-loss rankings use the newest recorded_at only.
billing_charges.invoice_status = 'OPEN' is the current bill. 'PAID' rows are prior months. current_balance equals the open charges until a new APPLIED credit reduces it.
The same plan name in July and September is a new month, not a duplicate. A duplicate is the same description in the same billing period, or is_duplicate_flag = 1.
A charge that already has an APPLIED credit must not be credited again.
